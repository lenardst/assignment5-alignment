\subsection*{(b) Characterizing model behavior}

\paragraph{\texttt{question\_only}.}
The model treats this prompt as a signal to keep generating math content. It
does not try to answer the question. Most outputs (76.8\% Cat.~3) add unrelated
word problems, emit LaTeX boilerplate, or repeat near-nonsense tokens
(``Pet Pet Pet\ldots''). The \verb|\boxed{}| format almost never appears.
Plain prompting does not put the model in a task-solving mode.

\paragraph{\texttt{r1\_zero}.}
Starting with \texttt{<think>} and the User/Assistant frame raises the format
rate to 62.0\%. The model writes a reasoning chain before \texttt{</think>},
then puts a number in \texttt{<answer>} tags. The arithmetic is usually wrong.
Cat.~3 failures (38.0\%) come from never closing \texttt{<think>}, placing the
answer outside \texttt{<answer>} tags, or adding an extra ``User:'' turn.
The prompt shapes format but not correctness.

\paragraph{\texttt{r1\_zero\_three\_shot}.}
Three worked examples raise the format rate to 95.0\% and accuracy to 18.65\%.
The examples teach the expected length and style. Chat-style failures become
rare. Cat.~3 failures drop to 5.0\%; most are outputs that end at
\texttt{</think>} with no \texttt{<answer>} tag. Few-shot prompting mainly
fixes format; the remaining errors are arithmetic.

\subsection{Deriving on-policy GRPO}

\begin{problembox}{baseline\_calcs}
Compute the variance of the policy gradient estimator (5 points).
\end{problembox}

Setup: $\policy(A=1) = p = \sigma(\theta)$, $r(A) = \mathbf{1}\{A=1\}$.

\paragraph{Useful identities.} The sigmoid derivative gives $\nabla_\theta p = p(1-p)$. So
\[
\nabla_\theta \log \policy(A=1) = \frac{p(1-p)}{p} = 1-p,
\qquad
\nabla_\theta \log \policy(A=0) = \frac{-p(1-p)}{1-p} = -p.
\]

\subsection*{(a) Variance of the unadjusted estimator}
\deliverable{An expression in terms of $n$ and $p$, accompanied by a derivation.}

Let $Z_i = r(A_i)\nabla_\theta \log \policy(A_i)$. With $r(A)=\mathbf{1}\{A=1\}$:
\[
Z_i =
\begin{cases}
1-p & \text{with probability } p, \\
0 & \text{with probability } 1-p.
\end{cases}
\]
So $\E[Z_i] = p(1-p)$ and $\E[Z_i^2] = p(1-p)^2$. The variance of one sample is
\[
\Var(Z_i) = p(1-p)^2 - p^2(1-p)^2 = p(1-p)^3.
\]
The samples are i.i.d., so
\[
\Var\!\left[\frac{1}{n}\sum_{i=1}^n Z_i\right] = \frac{p(1-p)^3}{n}.
\]

\subsection*{(b) Variance of the baseline-adjusted estimator}
\deliverable{An expression in terms of $n$, $b$, and $p$, accompanied by a derivation and some discussion.}

Let $Z_i = (r(A_i)-b)\nabla_\theta \log \policy(A_i)$. Then
\[
Z_i =
\begin{cases}
(1-b)(1-p) & \text{with probability } p, \\
b\,p & \text{with probability } 1-p.
\end{cases}
\]
The expectation is unchanged: $\E[Z_i] = p(1-b)(1-p) + (1-p)bp = p(1-p)$. The second moment is
\begin{align*}
\E[Z_i^2] &= p(1-b)^2(1-p)^2 + (1-p)\,b^2 p^2 \\
&= p(1-p)\bigl[(1-b)^2(1-p) + b^2 p\bigr] \\
&= p(1-p)\bigl[(1-p) - 2b(1-p) + b^2\bigr].
\end{align*}
Subtract $\E[Z_i]^2 = p^2(1-p)^2$ and factor:
\begin{align*}
\Var(Z_i) &= p(1-p)\bigl[(1-p)^2 - 2b(1-p) + b^2\bigr] \\
&= p(1-p)\,(1-p-b)^2.
\end{align*}
For the mean over $n$ samples:
\[
\boxed{\;\Var\!\left[\frac{1}{n}\sum_{i=1}^n (r(A_i)-b)\nabla_\theta \log \policy(A_i)\right]
= \frac{p(1-p)(1-p-b)^2}{n}.\;}
\]
The variance reaches zero at $b^\star = 1-p$. The optimal baseline is $1-p$,
not the expected reward $p$. The score function has nonzero size on $A=0$,
so the baseline must also account for that side.

\subsection*{(c) Variance with the population-mean baseline $b=p$}
Substituting $b=p$ in part (b):
\[
\Var\!\left[\frac{1}{n}\sum_i Z_i\right] = \frac{p(1-p)(1-2p)^2}{n}.
\]
Compared to part (a), the ratio is
\[
\frac{(1-2p)^2}{(1-p)^2}.
\]
The baseline-adjusted variance is lower than the unadjusted variance for
$0<p<2/3$, equal at $p=2/3$, and higher for $p>2/3$. At $p=1/2$ the adjusted
variance is zero. At $p \to 1$ the adjusted variance is much larger. The
population-mean baseline is sometimes better and sometimes worse, depending on $p$.

\subsection{Experiments}

Use GRPO to improve OLMo-2-0425-1B performance on GSM8K (10 points).

\subsection*{(a) Training script}
\deliverable{A script to run GRPO (standard, on-policy) on GSM8K and OLMo-2-0425-1B.}

The script is \texttt{scripts/grpo.py}. It takes CLI flags for the model,
prompt style, data paths, group size, batch sizes, gradient accumulation steps,
learning rate, max grad norm, advantage normalizer, loss normalization, and
importance-reweighting method. The main loop is:
\begin{enumerate}
  \item Parse hyperparameters. Load train (6{,}400 examples) and val
    (1{,}024 examples) splits of GSM8K.
  \item Start the vLLM server on GPU~1. Set the stop string to
    \texttt{</answer>} for \texttt{r1\_zero} prompts.
  \item Load the policy on GPU~0. Build AdamW($\beta_1=0.9$, $\beta_2=0.95$, wd$=0$).
  \item Start W\&B logging. Log all hyperparameters.
  \item For each rollout step: (i) sync policy weights into vLLM via NCCL;
    (ii) sample a rollout batch of $B{=}256$ completions ($G{=}8$ per prompt);
    (iii) call \texttt{grpo\_train\_step}; (iv) log train metrics.
    Every 10 steps evaluate on 1{,}024 val examples.
    Every 40 steps write a rollout JSON for inspection.
  \item Run a final val evaluation, save the checkpoint, and write
    \texttt{final\_metrics.json}.
\end{enumerate}

\subsection*{(b) Sanity check ($\sim$50 steps)}
\deliverable{Evidence that convinced you the script is correct.}

The full 200-step runs served as the sanity check. Three signals confirmed
correctness. First, all four seeds reached val reward $>42\%$ by the end of
training. This is well above the $25\%$ target. A broken loop would stay near
the baseline of $\sim$8\%. Second, rollout logging showed format adoption
within the first 40 steps. By step~40, most completions follow the
\texttt{</think>~<answer>~\ldots~</answer>} template; at step~0, they do not.
Third, val format reward climbed alongside total reward. This confirms the
reward function and generation pipeline are connected correctly.

\paragraph{Per-metric behavior.}
\begin{itemize}
  \item \textbf{Loss.} Stays near zero throughout (range $[-0.05, 0.00]$).
    This is expected. The GRPO objective is a surrogate. Only its gradient
    matters, not its value. Cross-seed spread is small.
  \item \textbf{Gradient norm.} Rises from $0$ to $\approx 1.0$ within the
    first few steps. It then stays at the \texttt{max\_grad\_norm} clip
    threshold. Updates are clip-limited almost every step.
  \item \textbf{Token entropy.} Drops steadily from $\approx 0.99$ nats to
    $\approx 0.12$ (halved by step~50, near-floor by step~100). The policy
    becomes much more predictable as it learns the format and consistent
    reasoning. The largest cross-seed spread is early ($\std$ up to $0.43$).
    It shrinks as all seeds reach low entropy.
  \item \textbf{Train reward.} Format reward is learned fast. It goes from
    $0.52$ to $\approx 0.89$ by step~50, then levels off near $0.91$.
    Total (answer) reward climbs more slowly:
    $0 \to 0.29$ (step~50) $\to 0.48$ (step~100), then levels off.
    Its mid-training cross-seed std is large ($\approx 0.23$) because seeds
    learn correct arithmetic at different rates.
  \item \textbf{Val reward.} Tracks train reward: format reaches $\approx 0.93$,
    total levels off at $\approx 0.45$. Despite noisy paths, all seeds end at
    nearly the same final val reward (end $\std = 0.007$).
  \item \textbf{Val response length.} Flat ($\approx 103$ tokens) through
    step~50, then grows to $\approx 134$ as the model adopts multi-step
    reasoning, then levels off. Early length spread across seeds is high
    ($\std \approx 32$, from pre-format rambling). It drops to $\approx 2$
    tokens by the end.
\end{itemize}
Variance between runs is highest in the first $\sim$100 steps. Entropy, length,
and answer reward differ a lot across seeds early on. By the end, all runs reach
very similar final validation reward and format. The procedure is stable at
convergence.

\subsection{Dr.\ GRPO}

\begin{problembox}{think\_about\_length\_normalization}
Think about length normalization (1 point).
\end{problembox}
\deliverable{A few sentences of discussion.}

Per-sequence normalization divides each sequence's total token loss by its
length. A token in a long sequence gets a smaller weight than a token in a
short one. This prevents long rollouts from dominating the gradient. It also
introduces a length bias. For an incorrect response, the per-token penalty
shrinks as the response grows. Long wrong answers are under-penalized. The
model is then pushed toward longer incorrect responses. This bias is identified
in the Dr.\ GRPO paper. Constant normalization divides every sequence's loss by
the same fixed number. Each token gets equal weight. This is closer to the true
policy gradient and avoids the length bias. Its scale does depend on the total
token count in the batch. Use per-sequence normalization when response lengths
vary a lot and stable updates matter. Use constant normalization when an
unbiased gradient estimate matters more.

\subsection{Rejection fine tuning}

\begin{problembox}{think\_about\_rft}
Think about RFT (2 points).
\end{problembox}
\deliverable{A few sentences of discussion.}

For binary reward, both objectives target the same gradient $\nabla\eta(x)$,
but not exactly at finite $G$. RFT keeps a $\nabla\log\policy$ term on correct
samples only. Its expectation is
$\E_y[\mathbf{1}\{r=1\}\nabla\log\policy] = \E_y[r\,\nabla\log\policy] =
\nabla\eta(x)$. Dr.\ GRPO keeps the term on all samples and subtracts the
group mean $\mu$. The mean $\mu$ includes the current sample. Because of this,
the subtraction does not vanish in expectation. It rescales the gradient by
$\tfrac{G-1}{G}$. The two estimators agree only up to this factor and match
exactly as $G\to\infty$. Dr.\ GRPO has lower variance because the group mean
is a valid baseline. RFT skips this correction. I would prefer Dr.\ GRPO when
groups have mixed rewards. The baseline then gives a real variance reduction.
I would prefer RFT when most groups are all-correct. In that case, Dr.\ GRPO's
advantage $r-\mu$ is near zero and its update vanishes. RFT still trains on
the correct rollouts and is simpler.

\subsection{MaxRL}

\begin{problembox}{derive\_difficulty\_reweightings}
Derive difficulty reweightings induced by different advantage normalizers (6 points).
\end{problembox}

\paragraph{Setup.} Write $\eta(x) = \E_{y\sim\policy}[r(y|x)]$. The standard
policy gradient is $\nabla_\theta J_\theta = \E_x[\nabla\eta(x)]$. The surrogate
target is $\nabla_\theta J_{\theta,w} = \E_x[w(x)\nabla\eta(x)]$. The inner
expectation over $\sim\policy(\cdot|x)$ satisfies
$\E_y[\nabla\log\policy(y|x)] = 0$. For any $f(x)$ independent of $y$, this
gives $\E_y[f(x)\nabla\log\policy(y|x)] = 0$.

\subsection*{(a) Dr.\ GRPO reweighting}
\deliverable{An expression in terms of a subset of the problem parameters, with a few sentences of justification.}

With $Z=G$ and $G\to\infty$:
\[
\frac{1}{G}\sum_{j=1}^G (r(y^{(j)}|x) - \mu)\nabla_\theta\log\policy(y^{(j)}|x) \;\longrightarrow\; \E_y\bigl[(r - \eta(x))\nabla\log\policy(y|x)\bigr].
\]
The mean-subtracted term gives zero contribution since $\eta(x)$ does not
depend on $y$. So the limit equals
$\E_y[r\nabla\log\policy(y|x)] = \nabla\eta(x)$. Taking expectation over $x$:
\[
\boxed{\;w(x) = 1.\;}
\]
Dr.\ GRPO weights all prompts equally. It matches the unbiased policy gradient
in the on-policy limit.

\subsection*{(b) GRPO (with std normalization) reweighting}
\deliverable{An expression with derivation.}

The estimator divides by the group std. For binary reward,
\[
\text{std}\;\xrightarrow{G\to\infty}\; \sqrt{\eta(x)(1-\eta(x))}.
\]
The numerator converges to $\nabla\eta(x)$ as in (a). Combining:
\[
\E_x\Bigl[\frac{\nabla\eta(x)}{\sqrt{\eta(x)(1-\eta(x))}}\Bigr]
= \E_x[w(x)\nabla\eta(x)] \;\Rightarrow\;
\boxed{\;w(x) = \frac{1}{\sqrt{\eta(x)(1-\eta(x))}}.\;}
\]
The weight is large at $\eta\approx 0$ and $\eta\approx 1$ and small at
$\eta=1/2$. GRPO upweights very easy and very hard prompts.

\subsection*{(c) MaxRL reweighting (divide by group mean)}
\deliverable{An expression with derivation.}

The estimator divides by $\mu$. With $G\to\infty$, $\mu \to \eta(x)$. So
\[
\E_x\Bigl[\frac{\nabla\eta(x)}{\eta(x)}\Bigr]
= \E_x[w(x)\nabla\eta(x)] \;\Rightarrow\;
\boxed{\;w(x) = \frac{1}{\eta(x)}.\;}
\]
The weight is large for hard prompts (small $\eta$) and small for easy prompts.
MaxRL upweights hard prompts.

\begin{problembox}{think\_about\_advantage\_normalization}
Think about advantage normalization (2 points).
\end{problembox}
\deliverable{A few sentences of discussion.}

The three options balance stability and bias. Std normalization keeps the
gradient norm roughly equal across groups. This stabilizes training. It also
upweights very easy and very hard prompts. Mean normalization (MaxRL) upweights
hard prompts. This is useful when the data has many easy examples. But it is
unstable when the group mean is near zero. No normalization (Dr.\ GRPO) is the
unbiased policy gradient. It weights all prompts equally. The gradient norm
then varies a lot across groups. Use std when training is unstable. Use mean
when the data has many easy prompts and you want to focus on hard ones. Use
none when you want an unbiased estimate.

\subsection{Importance reweighting / clipping}

\begin{problembox}{derive\_surrogate\_objectives}
Derive surrogate objectives for importance reweighting approaches (2 points).
\end{problembox}
\deliverable{An expression in terms of a subset of the problem parameters, accompanied by a derivation.}

\paragraph{Setup.} The pairwise estimator groups tokens into pairs
$(y_{2t-1}, y_{2t})$. For each pair index $t \in \{1, \dots, L/2\}$ define a
mixed policy. This policy samples all pairs from $\policyold$ except pair $t$.
Pair $t$ is sampled from $\policy$:
\[
\tilde\pi_t(y|x) =
\Bigl(\prod_{s\neq t}\policyold(y_{2s-1}|x,y_{<2s-1})\policyold(y_{2s}|x,y_{<2s})\Bigr)
\cdot \policy(y_{2t-1}|x,y_{<2t-1})\policy(y_{2t}|x,y_{<2t}).
\]

\paragraph{Surrogate.} The surrogate objective sums the reward under each
mixed policy:
\[
\boxed{\;J^{\text{pair}}_\theta = \E_{x}\!\left[\sum_{t=1}^{L/2}\E_{y\sim\tilde\pi_t}\!\bigl[r(y|x)\bigr]\right].\;}
\]

\paragraph{Derivation.} Take the gradient and reweight each term so all
tokens are sampled from $\policyold$. For a fixed pair $t$, the ratio of
$\tilde\pi_t$ to $\policyold$ is exactly the pair $t$ ratio:
\[
\frac{\tilde\pi_t(y|x)}{\policyold(y|x)}
= \frac{\policy(y_{2t-1}|x,y_{<2t-1})\policy(y_{2t}|x,y_{<2t})}{\policyold(y_{2t-1}|x,y_{<2t-1})\policyold(y_{2t}|x,y_{<2t})}.
\]
We apply the log-derivative trick to the pair $t$ factors only. The other
factors do not depend on $\theta$:
\begin{align*}
\nabla_\theta \E_{y\sim\tilde\pi_t}[r(y|x)]
&= \E_{y\sim\policyold}\!\Bigl[\tfrac{\tilde\pi_t(y|x)}{\policyold(y|x)}\,r(y|x)\,\nabla_\theta\log\bigl(\policy(y_{2t-1}|x,y_{<2t-1})\policy(y_{2t}|x,y_{<2t})\bigr)\Bigr].
\end{align*}
Summing over $t$ and over $x$ recovers the given pairwise estimator. The
surrogate above is therefore the objective for this estimator.

\texttt{clip} (token-level PPO clipping) is unstable across seeds. One seed

long sequences.

GSPO reports the fraction of \emph{sequences} clipped. With
$\varepsilon=3\!\times\!10^{-4}$, nearly every sequence is clipped (clip
fraction near $1$). GSPO caps one geometric-mean ratio per sequence. Even
near-total clipping leaves a bounded update. Token-level clipping caps
individual tokens but the rest of the sequence can still drift freely.

GSPO is far more stable than token-level clipping. \texttt{naive},
\texttt{noclip}, and \texttt{clip} would all likely benefit from a lower
learning rate or fewer off-policy steps. GSPO works well without further tuning.
The GSPO result is robust given its low seed variance. The failure of
\texttt{naive} is clear. The \texttt{clip} ranking is less certain because of
its high seed-to-seed variance. Its exact mean should be read with caution.

\end{problembox}
\deliverable{A few sentences of commentary.}

No reweighting has the highest bias and the lowest variance. It works when
$\policy$ and $\policyold$ are close. It breaks down once they drift apart.
PPO/GRPO token-level clipping is in the middle. It caps each ratio in
$[1-\varepsilon, 1+\varepsilon]$. This reduces variance at the cost of bias on
clipped tokens. This is the standard choice for off-policy LLM training. GSPO
clips a sequence-level geometric-mean ratio. It works better when sequences are
long and reward belongs at the sequence level. Use no reweighting for nearly
on-policy training, token-level clipping for the standard off-policy case, and
GSPO for long sequences.

\section{Try your own policy gradient estimator}
% =====================================================

\begin{problembox}{try\_your\_own}
Try your own policy gradient estimator (10 points).
\end{problembox}
\deliverable{Commentary, plots, and optionally mathematical derivations.}

\subsection*{Proposed estimator: leave-one-out baseline (LOO-GRPO)}

The standard GRPO baseline is the group mean. This mean includes the current
sample. The leave-one-out (LOO) baseline excludes the current sample. For
prompt $i$ and rollout $j$ define
\[
\mu_i^{(j)} = \frac{1}{G-1}\sum_{k\neq j} r(y^{(i,k)}|x^{(i)}).
\]
The estimator is otherwise identical to Dr.\ GRPO (constant normalization,
no std):
\[
\boxed{\;\hat g_{\text{LOO}} = \frac{1}{Z}\sum_{i=1}^B \sum_{j=1}^G \sum_{t=1}^{\text{len}(y^{(i,j)})}\bigl(r(y^{(i,j)}|x^{(i)}) - \mu_i^{(j)}\bigr)\,\nabla_\theta\log\policy\bigl(y_t^{(i,j)}\mid x^{(i)}, y_{<t}^{(i,j)}\bigr).\;}
\]
This changes one thing relative to Dr.\ GRPO: the baseline.

\subsection*{Theoretical motivation}

The group mean includes the current sample. The two are correlated. The LOO
baseline is independent of sample $j$ by construction. So the LOO estimator is
unbiased even at finite $G$, while the Dr.\ GRPO estimator carries an
$O(1/G)$ bias.

For binary reward, the difference is clear. The Dr.\ GRPO advantage for a
correct rollout is $1 - \mu_i$. Here $\mu_i$ already includes that rollout's
reward. The LOO advantage is $1 - \mu_i^{(j)} = 1 - (\mu_i G - 1)/(G-1)$.
This value is strictly larger. LOO gives a larger gradient signal on rare
correct rollouts and a stronger penalty on rare incorrect ones. The policy
gradient should focus most on samples far from the group average. LOO achieves
this.

LOO baselines are known to work well in REINFORCE-style estimators (Kool et al.\
2019; Richter et al.\ 2020). The cost is a tiny extra computation per group
(still $O(G)$).

\subsection*{Results}

LOO-GRPO was run against Dr.\ GRPO at 4 seeds with identical hyperparameters
(\texttt{lr=1e-5}, \texttt{baseline=loo}/\texttt{mean},
\texttt{advantage\_normalizer=none}, \texttt{loss\_normalization=constant},
200 rollout steps). Figure~\ref{fig:loo} shows final val reward.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.6\linewidth]{../experiments/writeup/plots/loo_grpo_reward.png}
  \caption{LOO-GRPO vs.\ Dr.\ GRPO: final validation reward (mean $\pm$ std, 4 seeds).}
  \label{fig:loo}
\end{figure}

\paragraph{Does it beat the baselines?}
LOO-GRPO ($0.458 \pm 0.009$) edges out Dr.\ GRPO ($0.446 \pm 0.027$) by
$0.012$ in mean final val reward. The LOO seeds are also more consistent
(lower std). This matches the theory: the LOO baseline is independent of
sample $j$. It gives a lower-variance gradient estimate at finite $G$. The gap
is small relative to the run-to-run variation. With only 4 seeds per variant,
it is not statistically significant. LOO-GRPO is a drop-in replacement for
Dr.\ GRPO. It adds no extra computation and shows a slight empirical advantage.
A larger sweep would be needed to confirm the improvement is robust.
